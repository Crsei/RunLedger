# RunLedger 缺失设置清单（对照 oh-my-pi SETTINGS_SCHEMA）

> 状态：差集快照完成（2026-08-21）。基线：oh-my-pi `packages/coding-agent/src/config/settings-schema.ts`（`SETTINGS_SCHEMA`，约 230 个键，typed schema + 强制 default）与 RunLedger `b23b900921f9` 基线的 `src/storage/settings-manager.ts`（当时的 `ProjectSettings`，13 个扁平可选字段，手写 sanitize 白名单）。本 worktree 的未提交 settings candidate 状态改由 [`../settings/README.md`](../settings/README.md) 记录，不反向改写这份差集快照。
>
> 范围：仅记录 **omp 独有 / RunLedger 未覆盖** 的设置；两方交集（`recap`、`hideThinkingBlock`、`enabledModels`、`theme`、`skills.enabled`、`autoTitle` 等）不重复列出。
>
> 图例：**缺失** = RunLedger 无对应能力与设置；**部分** = 能力或 CLI 面已有，但无对应 settings 键 / 形态不同；**已有** = 能力与设置均已覆盖（仅列关键对照）；**待核实** = 需对照 RunLedger 实现进一步确认是否缺失。

| omp key（类型，默认） | RunLedger 现状 | 核实要点 |

| `modelRoleStorage` / `modelTags` / `modelProviderOrder` / `cycleOrder` | 待核实 | 与 modelRoles 一同决策 |
| `defaultThinkingLevel`（enum, high；含 auto） | 待核实 | `thinkingLevel` settings + `--thinking` 已有（off…max 全级别）；`auto` 级别与预算映射需核实 |

## 附录 B：落位约束（若后续实现）

- 新字段必须进 `src/storage/settings-manager.ts` 的 `sanitizeProjectSettings` 白名单；未知字段沿用"丢弃 + stderr"语义，不破坏既有 settings 文件。
- 沿用既有 authority 规则：`recording` 仅用户级；`multiAgent`/`skills` workspace 层只能收窄；敏感 managed policy 不进 settings。
- `saveProjectSettings` 保持 0o600/0o700 与 read-modify-write 模式（TUI `/theme`、`/hide-thinking`、controller `persistSelection` 先例）。
- 新增 CLI/TUI 配置面优先复用既有 selector/command 体系，不直接让 TUI 写 JSON。
